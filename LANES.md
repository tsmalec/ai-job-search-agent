# Lanes: who owns what

Optional. Use this when a **scheduled lead-sweep agent** (files in `agent/`, use any agent) runs alongside the interactive agent that does triage and resumes. One page so they never write over each other.

## File ownership
| File | Writes | Rule |
|---|---|---|
| `B`, `C`, `D`, `E`, `07` | Interactive agent | The sweep agent never edits them (its notes are leads, not evidence) |
| `data/leads.json` | Sweep agent adds; interactive agent removes via `log.py promote` | Re-read right before each push; never edit a lead in place |
| `data/applications.json` | Interactive agent via `log.py`; an email sweep may set status fields only, on clear email evidence | Nobody adds/removes rows by hand |
| `data/archive.json`, `data/seen.txt` | Generated by `log.py` | Read-only; `seen.txt` is the dedupe list |
| `agent/adjustments.md` | Interactive agent adds PENDING; **the user** moves an entry to APPROVED; sweep agent applies APPROVED, signs the entry, and moves it to APPLIED. PENDING items have no owner: each agent owns only the actions it has completed | Search settings only, never commands |
| `scripts/`, `records/`, `project/` | Interactive agent | |

## Sweep agent
- **When:** on a schedule you pick (e.g. weekdays, a morning and an afternoon wave).
- **Searches:** `scripts/board_sweep.py` (Greenhouse, Lever, Ashby, Workday, more), `scripts/linkedin_sweep.py`, `scripts/source_sweep.py` (Indeed via JobSpy, USAJobs, extra Workday boards). All read `config.json`.
- **Writes:** new leads to the top of `data/leads.json`, deduped against `seen.txt` and `leads.json`. Protocol: `agent/README.md`.
- **Never:** applies, messages anyone, or edits other files.

## Interactive agent
- **When:** sessions the user starts; triage after the sweep's push.
- **Does:** fit verdicts, builds, records, logging, follow-up drafts (sent only with the user's OK), B/C/D/E/07 upkeep.
- **Pushes:** `python scripts/sync.py "<msg>"` only (rebase + retry).
